# Публикация ASM Tool из чистого исходного снимка

**Не переводите существующий приватный репозиторий в Public.** Удаление отчётов из последнего коммита не удаляет их из старых Git-объектов, предыдущих коммитов, тегов, веток и возможных архивов Releases.

## Подготовленный источник

Ветка `publication/clean-source-0.12.3` используется только для подготовки чистого содержимого. GitHub Actions **Clean source snapshot** экспортирует `ASM_Tool_0.12.3-source.zip` с файловым деревом без истории `.git` и `SHA256SUMS` рядом. Проверяет наличие 323/323 обязательных файлов лицензионного корпуса и отсутствие известных каталогов с архивными отчётами, переносными legacy locks и старыми сборочными workflow.

## Создание отдельного приватного репозитория

1. Скачайте проверенный исходный ZIP из успешного запуска Clean source snapshot. Проверьте его SHA-256 по приложенному `SHA256SUMS`.
2. Создайте **новый пустой приватный** репозиторий GitHub — без автоматического README, LICENSE, `.gitignore`, начальных коммитов, импортированной истории, старых веток или тегов.
3. Распакуйте ZIP в новую папку и создайте единственный начальный коммит.

```bash
cd ASM_Tool_0.12.3-source
test ! -e .git
git init -b main
git add -A
git commit -m "Initial source release: ASM Tool 0.12.3"
git remote add origin <SSH-ИЛИ-HTTPS-АДРЕС_НОВОГО_ПРИВАТНОГО_REPO>
git push -u origin main
```

4. Перед изменением видимости проверьте:

```bash
test "$(git rev-list --count --all)" = 1
test -z "$(git tag --list)"
git ls-files | grep -E '^(planning|reference|inventory|packaging|tools/(ci|patch123|portable_rc|qualification)|docs/patch123)/' && exit 1 || true
git ls-files | grep -E '^licenses/patch123/'
```

5. После этого проверьте GitHub: видимость Private, `main` с единственным исходным коммитом, без Releases с предыдущими архивами, без старых branches/tags; выполните независимый аудит секретов **текущих исходников и вложенных лицензий** и функциональные проверки приложения.

Только после проверки соответствующих лицензионных обязательств, безопасности исходников и необходимой квалификации выпуска можно решать вопрос публичной видимости.

## Границы

Тестовые фикстуры в `testdata/` используются действующими тестами и сохраняются вместе с исходным кодом. Они не являются внутренними аудит-отчётами, но сами тесты также требуют проверки перед утверждением полного регрессионного PASS. Оригинальные лицензии и GNU corresponding sources нельзя удалять ради уменьшения архива.

Это процедура нового начального коммита; перенос существующих веток, тегов или `.git` из исходного приватного репозитория **не допускается**.
