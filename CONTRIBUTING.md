# Вклад в ASM Tool

Текущее дерево относится к ASM Tool 0.12.3. Изменения должны сохранять безопасность области исследования, необходимость авторизации активных проверок и корректную диагностику неполных результатов.

## Организация изменений

Проверяйте актуальный `README.md`, `AGENTS.md`, архитектуру `internal/` и документы [docs/patch123](docs/patch123/) перед изменением контрактов. При изменении поведения приложите тест, который проверяет наблюдаемое поведение, а не дублирует код реализации. Не запускайте сканирование внешних доменов без разрешения владельца цели.

Перед предложением изменений, относящихся к Go:
```bash
go test ./...
go vet ./...
```
Сообщайте фактически выполненные проверки и их exit codes; если тесты не выполнялись, помечайте их `NOT_RUN`. Для Windows GUI дополнительно нужны .NET/WinUI-сборка и целевые проверки на Windows. Linux cross-build не подтверждает Windows GUI.

Не коммитьте `dist/`, `runs/`, локальные журналы исследований, credentials, токены, секреты, vendor SDK и временные bin/obj. Применимые лицензии сторонних компонентов должны сопровождать добавляемую зависимость.

## Сборка и выпуск

Исходники GUI: `ui/windows/`. Portable-комплектация: `packaging/` и `tools/`. Зафиксированные контрольные суммы официального кандидата: [RELEASE_ARTIFACT_VERIFICATION.md](docs/patch123/RELEASE_ARTIFACT_VERIFICATION.md).

Публикацию в Public, изменение тега и создание опубликованного GitHub Release следует проводить только после завершения security/licensing gates и отдельного решения владельца.
